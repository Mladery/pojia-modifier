# 行为规格 · 文件与数据层

> 本层是所有上层功能的地基。契约一旦违反，上层的"幂等/可逆"必然崩。

---

## 1. 文本读取

需要两种读取语义，用途不同，不可混用。

### 1.1 宽容读（用于"能读就读，读不动也不炸"）

**输入**：路径
**输出**：`(文本, 是否带 BOM, 行尾)` 三元组

规则：
- 以二进制打开，一次性读完。
- 首三字节若是 UTF-8 BOM（`EF BB BF`），剥掉，第二个返回值 `True`。
- 剩余字节按 UTF-8 解码；非法字节用替换字符顶替，**不抛异常**。
- 第三个返回值是探测到的行尾（`"\r\n"` 或 `"\n"`），规则见第 3 节。
- 文件不存在或读失败 → 抛异常（由调用方决定是否捕获）。

> **一次读、三个返回值**是硬要求。分成"读文本""查 BOM""测行尾"三次调用，会出现
> 三次之间文件被别的进程改掉、三个结论互相矛盾的窗口。

### 1.2 严格读（用于"内容必须可信才能拿来判断"）

**输入**：路径
**输出**：文本，或 `None`

规则：
- 任何异常（不存在、权限、IO）→ 返回 `None`。
- 有 BOM 先剥掉。
- 解码必须**完全成功**；出现非法字节 → 返回 `None`。
- 语义：`None` 表示"读不到可信内容"，**不等于空文件**。

### 1.3 空文件的判定

`None` 与 `""` 必须严格区分：
- `""` = 文件存在且为空。
- `None` = 读不到。
- 任何"读不到就写空"的逻辑都是缺陷。

## 2. 文本写入

### 2.1 原子写（唯一的底层写入口）

**输入**：路径、字节串
**输出**：成功 `True` / 失败 `False`

规则：
- 临时文件放在**同一目录**下，命名必须可识别且不会与用户文件冲突（例如 `~<原名>.tmp`）。
- 写入 → `flush` → `fsync` → 原子替换（Windows 用 `os.replace`，POSIX 用 `os.replace`）。
- 替换失败 → 删除临时文件 → 返回 `False`，**原文件保持不动**。
- 临时文件名固定，保证重入时不会堆积垃圾。

### 2.2 文本写入封装

**输入**：路径、文本、是否加 BOM、是否自动建目录
**输出**：`True`（写成功或被预演跳过）

规则：
- 预演模式：**直接返回 `False`，不碰磁盘**。
- 需要时先建父目录。
- 文本按 UTF-8 编码；`加 BOM` 为真则前置 `EF BB BF`。
- 走 2.1 的原子写；若原子写失败，退化为直接覆盖（保证功能不因临时文件问题中断）。
- 写入前必须记录"文件戳记"，供写后复核。

### 2.3 写后复核

写完立即回读，比对戳记：
- 一致 → 通过。
- 不一致 → 从备份还原，报错，计入失败。

## 3. 行尾与 BOM

- **行尾探测**：统计 `\r\n` 与单独 `\n` 的出现次数，返回占多数的那一种；两者都没有时返回 `\n`。只看前 400 字符即可，全文件统计没有额外收益。
- **BOM 保持**：读时记下有没有 BOM，写回时必须沿用。不许"顺手统一成无 BOM"。
- **行尾保持**：写回时把内容先统一成 `\n`，再整体转成探测到的行尾。**不要**直接对含 `\r\n` 的文本做 `\n → \r\n` 替换——那会把已有的 `\r\n` 变成 `\r\r\n`，而且二次写入会不断变长（幂等直接破掉）。
- 内置常量（政策正文、覆盖层、硬化段）内部以 CRLF 保存；写进文件前按上面那条统一成目标文件的行尾。

## 4. 哈希

三种，用途不同：

| 用途 | 算法 | 输出 |
|---|---|---|
| 政策哈希 | SHA-1 | 前 12 位十六进制 |
| 文件内容戳记 | SHA-256 | 前 16 位十六进制 |
| 完整性校验 | SHA-256 | 全量十六进制 |

规则：
- 文件哈希按 64 KB 分块流式读，不整文件载入内存。
- 输入不存在或读失败 → 返回空串，不抛异常。
- 政策哈希的输入拼接见 `00-overview` 4.2，拼接符为 `|`，末段固定字符串 `False`。

## 5. JSON 宽松解析

**问题**：目标是 JSON 文件，但用户可能写了注释、尾逗号、单引号、非标准转义。用标准解析器会失败，用正则改字符串又可能改坏。

**要求**：实现一个"只做定位、不做完整解析"的扫描器。

### 5.1 字符串边界定位

**输入**：整段文本、起始位置（指向一个 `"`）
**输出**：该字符串结束引号之后的位置

规则：
- 从起始引号的下一位开始逐字符走。
- 遇到 `\` 就跳过下一个字符（转义）。
- 遇到 `"` 结束。
- 走到文本末尾仍未闭合 → 返回文本长度（表示"没找到"）。

### 5.2 顶层对象提取

**输入**：整段文本
**输出**：`(对象起止位置, 顶层键名列表)` 或失败标记

规则：
- 跳过前导空白，必须遇到 `{`。
- 在深度 1 处收集键名：遇到 `"` 时用 5.1 取完整字符串，再看它后面是否紧跟 `:`，是则记为顶层键。
- 深度计数：`{`/`[` 加一，`}`/`]` 减一；深度回到 0 即对象结束。
- 字符串内部的花括号不计入深度。

用途：判断"这个 JSON 里有没有我们需要改的键"，以及"该键在哪一段"。

## 6. 备份

### 6.1 命名

- 默认后缀由目标决定（如 `.dshpurge.bak`），同一目标的所有备份后缀一致。
- 也允许调用方显式指定备份路径。

### 6.2 首次备份（关键）

**时机**：本工具第一次要改某个文件时。

规则：
- 备份文件已存在 → 什么都不做，直接返回。
- 备份不存在：
  - 先读当前内容（严格读）。
  - 若读得到，且**当前内容已经是本工具写的**（含本工具标记）→ **不建备份**，打印警告"原始备份已丢失"。
    理由：此时把注入版存成"用户原档"，撤回时会把注入版当成原样还原，等于没还原。
  - 否则 → 复制当前文件到备份路径（保留元数据）。

### 6.3 后续备份（防止覆盖旧备份）

**输入**：路径、后缀/备份路径、一个"内容是否仍是原版"的判定函数

规则：
- 备份不存在 → 走 6.2。
- 未提供判定函数 → 直接返回（不动备份）。
- 提供了判定函数：
  - 当前内容读不到，或判定为"不是原版" → 直接返回。
  - 当前内容是原版，且与备份内容**不同** → 先把旧备份归档一份（见 6.4），再用当前内容覆盖备份。
  - 相同 → 不动。

### 6.4 归档

把一份备份再抄一份到「归档目录」，文件名带时间戳与原因标签，避免后续覆盖把历史版本弄丢。

- 归档目录不存在则创建。
- 失败不影响主流程（静默）。

### 6.5 备份与还原的对称性

还原 = 把备份内容写回原路径。要求：
- 逐字节一致（含 BOM、行尾）。
- 还原后，如果原文件是本工具**新建**的，且还原后内容为空 → 可以删除该文件。
- 结构化配置文件（如 TOML）即使为空也不删——删了客户端起不来。

## 7. 清单

### 7.1 路径

脚本目录下的状态目录内，每个目标一份，文件名 = `<目标短标识>-targets.txt`。

### 7.2 读

- 文件不存在 → 返回空列表。
- 逐行读，跳过空行与 `#` 开头的行，两端去空白。
- 读失败 → 返回空列表，不抛异常。

### 7.3 写

- 去重 + 排序后逐行写入。
- 首行写一句说明性注释（`#` 开头），提示不要手改。
- 写失败静默（清单丢了不影响单次操作，只影响"彻底撤回"的完整性）。

## 8. 小工具

| 功能 | 契约 |
|---|---|
| **文件戳记（人类可读）** | 返回 `修改时间(yyyy-mm-dd HH:mm)  两空格  大小`；读不到返回 `-` |
| **大小格式化** | 小于 1024 显示 `N B`；否则按 KB/MB/GB 保留一位小数 |
| **相对路径显示** | 能把绝对路径压成相对安装根的短形式，用于日志；压不了就原样返回 |
| **Windows 长路径** | 路径超过 240 字符时加 `\\?\` 前缀；未超长原样返回；非 Windows 不加 |
| **清字节码缓存** | 启动早期删除脚本目录下的 `__pycache__`，避免明文常量被编译进 `.pyc` |
| **时间戳** | `yyyyMMdd-HHMMSS`（用于文件名）；ISO 8601 秒精度（用于护照） |
