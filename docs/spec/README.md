# 重写规格 · 索引

这套文档的唯一用途：**让一个没看过现有实现的 AI，写出行为等价的另一份实现。**

## 怎么用

1. 把 `00` 到 `50` 六份文档整体交给实现方。
2. 实现方**只读这六份文档与 `tests/contract/`**，不读 `src/` 下任何文件。
3. 实现方按层交付，每层单独可测。
4. 替换时按层替换，不整体替换——具体怎么换见 `REPLACE.md`。

## 分层与顺序

| 顺序 | 文档 | 覆盖 | 依赖 |
|---|---|---|---|
| 1 | `00-overview.md` | 术语、不变量、数据模型、错误约定 | 无 |
| 2 | `10-io.md` | 文本读写、哈希、JSON 扫描、备份、清单 | 00 |
| 3 | `20-locate.md` | **17 个目标的固定路径表**、兜底链、进程表、手动目录、选择器、权限 | 00、10 |
| 4 | `30-inject.md` | 政策组装、三种注入形态、状态判定、云记忆 | 00、10 |
| 5 | `40-targets.md` | 目标契约、17 个目标形态、三个特殊流程 | 00、10、20、30 |
| 6 | `50-cli.md` | 护照、体检、任务、参数、菜单、编排 | 全部 |

**必须按顺序做。** 后一层依赖前一层的接口；跳层会导致返工。

`REPLACE.md` 不在编号序列里，它是给**接手替换的人**看的：层与现有代码的对应、
不许改的出口名字、每层的验收顺序。

## 交付形态

每一层交付一个独立模块，对外只暴露该层契约里列出的能力。内部实现自由。

接口对齐原则：
- 文档里的"概念名"不要求一致，但**参数含义与返回值形状**必须一致。
- 返回 `None` 与返回空串的语义差别必须遵守（见 `10-io` 1.3）。
- 布尔返回值统一表示"是否成功"，不要用布尔表示"是否有变化"。

## 验收

每层交付后立刻跑：

```
python -m pytest tests/contract -q --basetemp=/tmp/pt
```

全绿才算该层完成。红的话按用例名（C1…C11）定位到 `REPLACE.md` 第 5 节的表。

**为什么是 `tests/contract` 而不是 `tests/`**：`tests/` 里那 300 个用例是白盒的，
直接调用现有实现的内部函数名。新实现一改名它们就全红，但产品其实没问题。契约测试
只看命令行与磁盘字节，实现怎么改都不影响。

`--basetemp` 不能省：默认临时目录在 Windows 上会堆到几百个文件，触发批量删除确认，
pytest 会以 exit=1 结束，看起来像测试失败。

## 已知的坑（实现方必读）

1. **不要用"先删后判"的顺序**处理整段替换。已注入的文件会被清空一半。
2. **TOML 的键必须落在顶层**，否则会被吞进最后一张表，注入静默失效。
3. **读失败不等于空文件**。拿空串覆盖是数据丢失。
4. **预演与只读动作不写日志**。这是用户能直接观察到的承诺。
5. **护照里存纯数字版本号**。带后缀会让所有已注入机器被判过期。
6. **asar 的 unpacked 条目缺失时回落到数据区**，不要静默跳过。
7. **进程表要缓存，但杀进程后必须失效**。
8. **`add` / `dump` / `read_text` / `write_text` 这类名字**如果实现方想用，注意别和标准库的 `set.add`、`json.dump`、`pathlib.Path.read_text` 撞车。
9. **行尾转换要先归一再加回**。直接对含 `\r\n` 的文本做 `\n → \r\n` 会得到 `\r\r\n`，而且每次重写都长一截——幂等直接破掉。同理 `rstrip("\n")` 遇上 CRLF 会留下一个孤立的 `\r`。
10. **BOM 要跟着还原路径走**。备份里有 BOM，但还原时若按 utf-8 解码再编码，BOM 就没了。整文件还原应该走字节复制。

## 边界

本规格覆盖 **8.0 那套核心逻辑**。以下不在范围内，替换时保持现状不动：

- 图形界面
- 安装包与自更新
- macOS 签名 / 重签
- Git Bash 接管
- 人格片段库
- 运行时守卫
- 取证与免责声明
