# 行为规格 · 护照、体检、任务、命令行

---

## 1. 护照

### 1.1 路径

目标专属目录下的固定文件名（每个目标目录一份）。

### 1.2 读

- 不存在 / 不是 JSON / 缺关键字段 → 返回"无护照"，**不抛异常**。
- 读到但字段类型不对 → 该字段按默认值处理，其余字段照用。

### 1.3 写

- 读-改-写：保留原有 `history`，追加本次记录。
- `history` 只保留最近若干条（防止无限增长）。
- 写失败要报出来（护照丢了会导致下次判不出"已注入"）。

### 1.4 由护照派生的判定

| 判定 | 规则 |
|---|---|
| 当前版本号 | 取 `version` 字段，按 `数字.数字` 解析；解析不出当 `0.0` |
| 是否需要跨版本重写 | 护照版本 ≠ 程序版本 → 是；无护照 → 是 |
| 人格是否过期 | `persona_hash` 非空且 ≠ 期望哈希 → 是；护照里没记过 → 否（不白写大文件） |
| 上次动作 | `last_action`，用于体检输出 |

### 1.5 版本号约定

- 护照里存的版本号**必须是纯数字**（如 `1.0`）。
- 显示用的后缀（如 `-mod`）只出现在界面与横幅，**不进护照**。
- 理由：后缀一变，所有已注入的机器会被判成"过期版"，用户看到一片假警报。

## 2. 体检（只读）

### 2.1 通用契约

- 全程不写盘、不备份、不改文件、不写日志。
- 输出按目标分组，每行一个结论，带级别前缀。
- 最后给一行总结：全绿 / 有 N 项需要处理。
- 有 `fail` 级 → 退出码 `1`。

### 2.2 每个目标要查的项

1. 目录是否存在、是否是有效安装。
2. 主配置文件是否存在、大小是否合理。
3. 是否已注入；注入的是哪一版（哈希是否等于当前）。
4. 备份是否存在；备份里有没有本工具标记（有则说明备份已失效）。
5. 护照是否存在；版本是否与程序一致。
6. 是否存在历史遗留的旧方案残留（如旧标记块），有则提示"重跑一次会自动清理"。
7. 该目标特有的检查（见下）。

### 2.3 密钥扫描

**目的**：配置文件里可能明文存着 API Key、token、cookie。

契约：
- 只报**位置与形态**，绝不打印密钥原文。
- 报的内容：行号、键名、脱敏后的值（保留首尾各若干字符，中间用固定符号替代）。
- 覆盖范围要宽：`key` / `token` / `secret` / `password` / `passwd` / `cookie` / `credential` / `auth` / `bearer` 等都要命中。
- 额外扫 `base_url` 一类的字段：若 URL 里内嵌了账号密码，也要报（只报"内嵌了凭据"，不回显）。
- 不读该配置引用的其他文件（体检不扩散）。

### 2.4 版本一致性

- 程序版本 vs 护照版本 vs 目标里实际注入的哈希，三者不一致要报。
- 报的时候要说清"哪个是哪个"，不要只给一个布尔。

## 3. 计划任务

**目的**：让注入保持有效（客户端升级会覆盖文件）。不是常驻进程。

### 3.1 任务

两个，名字固定：

| 任务 | 触发 | 作用 |
|---|---|---|
| 刷新 | 每 30 分钟 | 静默跑一次注入（幂等） |
| 登录 | 用户登录时 | 同上 |

### 3.2 契约

- 任务动作 = 用当前解释器运行本脚本，参数为"静默 + 全部目标"。
- 创建前先查是否已存在同名任务；存在则先删再建（避免参数不更新）。
- 创建后要**校验任务确实指向本脚本**：只判断"任务存在"不够，指向错脚本等于静默失效。
- 删除只删自己那两个名字，其他任务一概不碰。
- 权限不足（非管理员）→ 明确提示，不静默失败。
- 批量查询任务名时只起一次子进程；拿不到再退化为逐个精确查询。

### 3.3 POSIX

用 `crontab` 或 `systemd --user timer`。契约同上：只增删自己那一条，其余原样保留。

### 3.4 旧任务名清理

历史版本用过别的任务名。清理时：
- 只删"已知的旧名字"列表里的任务。
- 不按前缀模糊匹配（会误删用户自己的任务）。

## 4. 命令行

### 4.1 参数分组

**动作（互斥，选一个）**

| 参数 | 作用 |
|---|---|
| `--apply` | 注入 |
| `--revert` | 撤回 |
| `--restore` | 从备份还原（不删本工具目录） |
| `--check` | 只读体检 |
| `--status` | 只读状态 |
| `--snapshot` | 生成当前状态快照 |
| `--compare` | 与上次快照对比 |
| `--update` | 检查并更新自身 |
| `--uninstall` | 卸载（删程序，保留状态与备份） |
| `--purge` | 彻底清除 |

**范围**

| 参数 | 作用 |
|---|---|
| `--target <key>` | 指定目标，可重复或逗号分隔；缺省为全部 |
| `--<key>-dir <path>` | 手动指定某目标的目录 |
| `--pick <key>` | 弹目录选择窗口 |
| `--clear` | 清除记住的手动路径 |

**修饰**

| 参数 | 作用 |
|---|---|
| `--dry-run` | 预演，不落盘 |
| `--force` | 已注入的也强制重写 |
| `--yes` | 跳过确认 |
| `--quiet` | 只输出错误 |
| `--deep` | 深度探测（触发有界遍历） |
| `--pause` | 结束后等回车（快捷方式用） |

**人格**

| 参数 | 作用 |
|---|---|
| `--persona <file>` | 指定人格文件 |
| `--persona-name <name>` | 设置内置人格的称呼 |
| `--persona-set <names>` | 设定启用的人格片段组合 |
| `--persona-list` / `--persona-show` / `--persona-explain` | 只读查看 |

**其它**：`--guard`（运行时守卫）、`--git-bash`、`--mac-check`、`--resign`、`--gui`、`--menu`、`--version`、`--help`。

### 4.2 约定

- 无参数启动 → 进图形界面（本机网页 UI）；`--menu` 进交互菜单。
- `--quiet` 下不得有任何非错误输出。
- 未知目标 → 报错并列出可选值，退出码 `1`。
- `--version` 输出一行：`<显示版本>`。

## 5. 交互菜单

### 5.1 结构

一级菜单列出可用动作（注入 / 撤回 / 检测 / 体检 / 快照 / 对比 / 清理 / 退出），选中后进入目标多选。

### 5.2 契约

- 目标列表要显示：短标识、显示名、当前状态（严格/宽松/过期/未安装）。
- 默认勾选"已检测到"的目标；一个都没检测到则退回全部。
- 用户取消 → 什么都不做，退出码 `0`。
- 只读项（检测、体检）不得触发任何提问式交互（不得弹"输入 A 或 B"）。
- 非交互环境（无 TTY）→ 不进菜单，直接报错说明需要参数。

---

## 6. 主流程编排

### 6.1 注入

```
解析参数 → 解析目标集合 → 逐个目标：
    定位 → 校验安装 → 判定状态
        已是最新且非 --force → 跳过
        否则 → 备份 → 写入 → 复核 → 写护照 → 记清单
    单目标异常 → 记录失败，继续下一个
→ 汇总（成功 N / 跳过 M / 失败 K）→ 退出码
```

### 6.2 撤回

```
逐个目标：
    有护照 → 按护照记录的路径还原
    无护照 → 按清单还原
    都没有 → 只删本工具写的块/字段
→ 清理解包目录、专属目录、清单条目
→ 汇总 → 退出码
```

### 6.3 只读动作

`--status` / `--check` / `--snapshot` / `--compare` 全程只读：
- 不写日志（哪怕日志目录存在）。
- 不建目录。
- 不更新护照。

### 6.4 汇总输出

最后必须有：
- 每个目标的最终状态一行。
- 总计：成功 / 跳过 / 失败。
- 有失败时给"怎么修"的一句话。

---

## 7. 日志

- 位置：脚本目录下的固定文件名。
- 格式：`[时间] [目标] 消息`。
- 预演与只读动作**不写日志**。
- 日志失败不影响主流程。

---

## 8. 验收要点

- `--dry-run --apply` 之后，磁盘上没有任何新增/修改的文件（含日志、护照、备份）。
- `--status` 在非管理员下也能跑完，不报权限错误。
- 计划任务创建后，用查询命令能验证"动作指向本脚本"。
- `--quiet` 下 stdout 为空（无错误时）。
- 无参数启动进图形界面；`--menu` 进菜单；`--gui` 也进图形界面。
