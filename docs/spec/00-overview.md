# 行为规格 · 总纲

> 本文档描述「程序必须表现出什么行为」，不包含任何实现代码、标识符或注释。
> 实现者只依据本规格与验收用例编写，不参考任何既有实现。

---

## 0. 给实现者的约定

1. **只用本规格 + `tests/` 里的用例**。用例断言的是可观察行为（文件字节、退出码、输出关键字），不是内部结构。
2. **命名自由**。规格里出现的名字是概念名，不是必须使用的标识符。
3. **顺序自由**。只要满足"不变量"与"验收"，内部结构随意。
4. **不要试图猜测原实现的写法**。规格没说的地方，按最直接的方式实现。

---

## 1. 产品定义

给本机已安装的若干 AI 客户端，统一注入一段「操作者人格 + 宽松政策」文本，使其在会话开始时读到这份文本；并能在任何时候整块撤回到注入前的状态。

一句话：**批量注入 + 可逆撤回**。

不做的事：不改客户端二进制、不联网、不收集用户数据、不驻留后台进程（计划任务除外，且只调用本程序）。

---

## 2. 术语

| 术语 | 含义 |
|---|---|
| **目标** | 一个受支持的 AI 客户端。有唯一短标识（如 `dsh`）、显示名、安装根、以及一个「客户端会读取的文本文件」 |
| **注入** | 把政策文本写进目标读取的那个文件 |
| **整段替换** | 注入形态之一：目标文件里的某一段整体被替换掉 |
| **标记块** | 注入形态之一：在目标文件里插入一对首尾标记，中间是注入内容 |
| **字段注入** | 注入形态之一：目标文件是 JSON/TOML，只改其中一个键的值 |
| **护照** | 每个目标目录下的一份 JSON，记录本工具对它做过什么 |
| **清单** | 脚本目录下的一份文本文件，逐行记录被本工具改过的文件路径 |
| **基准备份** | 第一次改某文件前，把它的原始内容存下来的那份副本 |
| **预演** | 只计算会做什么、不落盘的模式 |
| **严格态** | 目标文件里没有本工具写的任何内容 |
| **宽松态** | 目标文件里有本工具写的内容 |

---

## 3. 全局不变量

违反任何一条即为缺陷，验收用例会覆盖。

**I1 · 幂等**
同一初始状态下连续执行两次，第二次不得改变任何文件的一个字节。

**I2 · 可逆**
任何写入之前，必须已经存在一份能还原到「写入前字节」的备份。执行撤回后，目标文件必须与首次注入前逐字节相同（包括 BOM 与行尾）。

**I3 · 原子**
写入一律「先写同目录临时文件 → 再原子替换」。任何时刻磁盘上不得出现半截文件。替换失败时原文件必须完好。

**I4 · 不越界**
只改本工具自己写入的部分。用户原有的内容一个字不动，不重排、不格式化、不统一缩进。

**I5 · 只读不落盘**
预演模式与检测模式下，不得创建/修改/删除任何文件，包括日志文件。

**I6 · 编码保真**
读取时识别并记住：UTF-8 BOM 有无、行尾是 LF 还是 CRLF。写回时原样保留。

**I7 · 单点失败不扩散**
一个目标出错，其余目标继续执行。全部结束后统一汇总。

**I8 · 退出码**
`0` = 全部成功；`1` = 至少一项失败。检测模式额外约定：有致命项时 `1`，否则 `0`。

## 4. 数据模型

### 4.1 政策文本的构成

最终注入到客户端的文本 = 四段顺序拼接：

1. **哈希头**（一行，见 4.3）
2. **用户自定义人格**（可选；若用户没提供则跳过）
3. **政策正文**（内置常量，CRLF 行尾）
4. **硬化段**（内置常量，CRLF 行尾）

此外还有一段**覆盖层**（内置常量），按目标类型决定插在正文之后还是整体替换，见 30-inject。

### 4.2 政策哈希

```
hash = sha1( 用户人格 + "|" + 政策正文 + "|" + 覆盖层 + "|False" ) 的前 12 位十六进制
```

- 用户人格为空时按空串参与计算（不是跳过）。
- 末位固定是字符串 `False`。
- 哈希**不包含**硬化段。这是刻意取舍：硬化段增删不能让所有已注入的机器被判成"过期"。

哈希头格式：`<!-- <标记前缀><哈希值> -->`，单独一行，行尾 CRLF。

### 4.3 护照（JSON，每个目标一份）

存放位置：目标专属目录下，文件名固定。

| 字段 | 类型 | 含义 |
|---|---|---|
| `tool` | string | 固定标识，用于认出"这是本工具写的" |
| `version` | string | 写入时的版本号，**纯数字**（如 `1.0`），不带后缀 |
| `target` | string | 目标短标识 |
| `root` | string | 目标安装根 |
| `config` | string | 主配置文件路径 |
| `instructions` | string | 指令文件路径（若该目标用独立文件） |
| `agents` | string | 附加文件路径（若该目标用），否则空串 |
| `agents_created` | bool | 附加文件是本工具新建的还是原本就有的 |
| `mode` | string | 注入模式名 |
| `last_action` | string | `apply` / `revert` |
| `last_apply_time` | string | ISO 8601，秒精度 |
| `echo_word` | string | 自证口令词 |
| `persona_hash` | string | 上次注入用的政策哈希 |
| `file_stamps` | object | 文件路径 → 戳记（大小+哈希短值），用于检测外部改动 |
| `created_by_other` | string | 非空表示这份护照是别的工具/别的版本写的 |
| `history` | array | 追加式操作记录，最多保留最近若干条 |

护照读不出来（不存在/损坏/不是 JSON）时，一律当作"没有护照"，不得抛异常。

### 4.4 清单（文本，脚本目录一份）

- 一行一个绝对路径。
- 以 `#` 开头的行是注释，读取时忽略。
- 空行忽略。
- 写入时去重 + 排序。
- 用途：撤回时知道"本工具改过哪些文件"，避免漏还原。

### 4.5 标记块

用于"追加式"客户端（用户自己的内容与注入内容共存在一个文件里）。

- 首标记与尾标记各占一行，形如 `<!-- 前缀:BEGIN -->` / `<!-- 前缀:END -->`，或对应语言的注释语法。
- 中间是注入内容。
- 同一文件里**只能有一个**本工具的块。
- 移除时连同标记行一起删；若文件删完只剩空白，且该文件是本工具新建的，可连文件一起删。
- 标记字符串必须足够独特，不与常见文本冲突。

### 4.6 文件戳记

对某文件计算的短标识：`文件字节数` + `内容 sha256 前 16 位`。用于：
- 判断文件在本工具写入之后有没有被外部改动过；
- 撤回时决定"能不能直接覆盖"还是"必须报警"。

---

## 5. 错误处理约定

1. 所有对外失败都转成**一行中文说明**，不打印 traceback。
2. 失败信息里必须带：哪个目标、哪个文件、什么原因（可选带建议动作）。
3. 读取失败 ≠ 空文件。读不到内容时**绝不能**拿空串去覆盖原文件。
4. 写后必须复核：写完立即回读，比对戳记；不一致就回滚到备份并报错。
5. 权限不足（如计划任务需要管理员）时，说明"需要管理员"，不静默失败。

---

## 6. 验收方式

- `tests/` 下全部用例通过。
- 手工验证四条：注入 → 再注入（字节不变）→ 撤回（字节回到原样）→ 预演（不产生任何文件）。
- 跨平台：Windows 必须跑通；macOS / Linux 至少不因路径分隔符、行尾、大小写差异崩溃。
