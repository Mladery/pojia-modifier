# 研发缘由

## 问题在哪

这些 AI 客户端（WorkBuddy、Cursor、Trae、Codex CLI、Claude Code…）都内置一份系统提示词，规定模型用什么身份、守什么规矩、怎么拒绝。这份提示词随安装包发下来，用户在界面上改不到：有的藏在打包文件里，有的编译进可执行文件，有的走服务端下发。想换成自己的设定，只能去翻安装目录、找到那份文件、按它自己的格式写进去 —— 每换一个客户端，这套活就得重做一遍，格式还各不相同。

## 三类现成做法，都不合用

| 做法 | 问题 |
|---|---|
| 手动改文件 | 17 个客户端 17 套路径与格式；改完没备份，客户端一升级就被覆盖；写错一个字节整份文件可能报废 |
| 带激活码 / 云控的「增强版」 | 功能要联网解锁，配置从服务端下发，随时可能被远程关掉；代码不公开，你没法确认它到底往你机器上写了什么 |
| 只在对话里贴一段提示词 | 每次新会话都要重贴；不进系统提示词，优先级低于内置规则，该拒还是拒 |

## 本项目的做法

把「找到那份文件 → 备份 → 按格式写进去 → 校验 → 能一键还原」这一整套固定下来，做成一个零依赖的脚本：

- **一份人格，17 个客户端共用。** 每个客户端的路径与格式差异吃在各自的适配类里，用户只维护一份文本。
- **改前必留旁路备份，`--revert` 一键回原样。** 备份放在客户端升级与清理工具够不到的地方。
- **全程离线，不发任何网络请求。** 不联网解锁、不要账号、不做云控下发 —— 这三样正是上一类方案最容易变卦的地方。
- **当场能自证。** 发一句固定口令，看回复里有没有那行标记，不用靠「感觉好像生效了」。
- **源码全公开。** 每一行都能核对；发布的 exe 由仓库 Actions 从同一份源码构建。

## 边界

只动**你自己有权管理的本机**上的提示词文本。不改软件本体、不碰服务端、不伪造请求、不分发任何客户端的副本。能做什么、不能做什么，见[完整免责声明](disclaimer.md)。
