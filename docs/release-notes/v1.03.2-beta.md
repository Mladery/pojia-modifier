# 破甲修改器 v1.03.2-beta

测试版。这一版加了三个目标：Reasonix、Trae CN、Qoder CN。目标数从 17 个变成 20 个。

## 新增目标

三个目标的配置根都不是「同名文件夹」那么直白，落点是实测过的，不是照着名字猜的。

### Reasonix

- 配置根默认在 `%APPDATA%\reasonix`，**不是** `~/.reasonix`。后者只是运行时放锁的空目录（一份配置都没有），拿它当根会让工具以为装了却找不到文件。
- 落点是根目录下的 `AGENTS.md`。这个客户端按 `AGENTS.md` / `REASONIX.md` / `CLAUDE.md` 分层加载：用户全局 → 祖先目录链 → 项目目录 → `*.local.md`，最后折进系统提示的一块里。写用户全局那份，作用于所有工作区。
- 没走 `config.toml` 里的 `[agent] system_prompt_file`：那是整份替换式注入，会把用户自己写的系统提示顶掉，而且要求绝对路径，写错了不报错、只是静默不生效。
- 该客户端自己的 `rules/` 目录也支持，但带 `paths:` 声明的规则会延后一回合送达；本工具写的是常驻文件，不依赖那个目录。

### Trae CN

- 配置根 `~/.trae-cn`，落点 `rules/project_rules.md`。
- 这个客户端同时加载两个规则目录：`rules/`（项目级规则文件）和 `user_rules/**/*.md`（用户级规则）。后者不归本工具管，只会在体检里列出来，提醒你那儿还有别的规则同时在生效。
- 工程仓库里的 `.trae/rules/` 是仓库自己的东西，属于版本控制范围，本工具不碰。
- 国际版 Trae 仍在 `~/.trae`，由上一条 `trae` 目标负责；国内版和国际版可以并存，各打各的。

### Qoder CN

- 配置根 `~/.qoder-cn`，落点 `agents/purge/qodercn.md`，另外在 `skills/purge/SKILL.md` 写一份技能包。
- agent 文件必须带 YAML 头（`name` / `description` / `permissionMode`），头在最前面，块在头下面。头不在最前，客户端会把整份文件当成一份没有元数据的普通 markdown，agent 等于没装。
- 技能包是本工具新建的整份文件，撤回时整份删掉，不留空壳；主文件撤回时按原来的头还原（原来没有头就还原成没有头）。
- `memory/MEMORY.md` 是账号级的本地索引，云端还有一份，本工具不碰，体检里只提示它在。
- 这个客户端的政策文本在服务端下发，本地包里没有可替换的政策块。注入走的是 agent + 技能这两层行为契约，不是改本地策略文件。

## 问题修复

- 修复第二落点在撤回时不被清理的问题。原来清理写在「摘块」分支里，而撤回到这一步之前会先检查主文件有没有干净备份，有就直接还原返回了 —— 分支永远走不到，技能包留在盘上。现在清理提到一切早退之前，并且直接使用调用方给的配置根定位第二落点，不再靠主文件路径上溯猜。
- 技能文件的 YAML 头不再被 agent 的头覆盖：头部 `name` 不是本工具的 agent 名时原样保留。
- 注入前会先摘掉更早版本留下的块（`POJIA-NEXT-INJECT` / `POJIA-CE-MIRROR`），同一个文件挨过不同版本时不会两层叠在一起。

## 现在的支持范围

20 个目标：DSH、WorkBuddy（国际版/国内版）、ZCode、Codex、Cursor、Claude Code、Antigravity、Qwen、iFlow、Trae、Trae CN、CodeBuddy、OpenCode、Windsurf、Cline、Copilot CLI、Kiro、Reasonix、Qoder CN。

## 验证

- 自检 `tools/selftest.py`：20 个目标逐个跑「注入 → 再注入 → 撤回」，20/20 通过，二次注入字节不变、撤回回到原样。
- 契约测试：63 项全部通过，含 `--help` 必须列出全部 20 个 `<目标>-dir` 开关这一条。
- 本机三个客户端实测：注入三家都成功，`--status` 全部「宽松态·当前」，撤回后技能包删除、agent 文件还原。
