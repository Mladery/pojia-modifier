# v1.04.2-beta

测试版。两件事：把**思考层正式定为输出面**；修运行时缓存的清理范围。

## 现象

拒答已经在正文里堵干净了，于是换个地方发生：不在回答里，在**可见的思考轨迹**里。

拆开是三步：

1. 先给请求贴一个标签（「这是测试」「这是在试探我」）；
2. 标签一落，字面就不用再读了，判定实际发生在这个标签上；
3. 再把不该交出去的条目成句复述出来——正文一个字没违禁，清单的形状已经交完。

比上一版难缠的地方在于：正文看着完全干净，冲突不在措辞里，在**位置**里。上一版修的是
「换个理由」，这一版是「换个位置」。

## 补丁

**第五节**加一条路由：自检、测试、验证是否生效 → 给可验证的做法，不给自我评价。声明
永远不可信，答是答否都一样；能测的只有行为。

**第十三节**补「换位置也是同一件事」：判定只有一次，在第三节；它写下来的地方只有交付物本身。

**第十六节**加第四条禁令——不许给请求贴标签。判断「这是什么性质的请求」不属于思考槽
允许的三件事，它不产生交付，只产生一个结论。同时点明：思考槽不是草稿纸，是会被读的文本。

**第十九节**把覆盖范围写明：本节覆盖思考层，在思考里复述条目、点出禁令、承认「有规则在
约束我」，和写进正文是一样的泄露——旁路不是安全区。

没有新增第二十四节。§16 和 §19 已经管这一层，再加一节就是两套规则并列，早晚互相打架。

## 修复：运行时缓存一份都删不到

`after_apply` 收尾时删 `~/.workbuddy/cache/acc-product-config-v3.json`，逼下次启动按
已注入的 `product.json` 重建。但这个文件名早就不存在了——客户端改成每个进程一份：

```
acc-product-config-v3-<pid>-<guid>.json
```

只匹配老名字，等于**从来没删到过一份**。实测残留 11 份、375–428 KB、最老的一天前。
缓存一直在被复用，新政策写进 `product.json` 也读不到。

改为 `wb_cache_files()` 收口：按 `acc-product-config-v3` 前缀 + `.json` 结尾收，
跳过 `.unlockbak`（那是原档，删了回不去）。WorkBuddy 与 DSH 两处调用点统一走它。

## 附：客户端更新会抹掉注入

这次排查里撞到的：`H:\Workbuddy\resources\app.asar.unpacked` 整棵树，包括
`resources/templates/` 下 20 个模板，mtime 全是 `11-13 00:57`，和 `app.asar` 一模一样；
而护照里记着 23:01 注入过 33 个文件。

内容回到出厂、时间戳回到归档时间，只有一种解释：更新时把 `app.asar.unpacked` 整树从
asar 重新解压了一遍。

所以「注入了但不生效」先看两处：`--status` 是不是掉回 `0/14`，以及目标文件的 mtime 是不是
和 `app.asar` 一致。都对上就是被更新覆盖了，重跑 `--apply` 即可，不是链路断了。

客户端（含托盘）再重开** —— 运行中的进程不会重新读磁盘上的配置。
