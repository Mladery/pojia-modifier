# v1.03.6-beta

测试版。一个撤回范围的修复：`--revert` 只拿掉我们写的那几行，不再把文件搬回
几天前的样子。

## 问题修复

**撤回会连带回滚别人写进同一文件的内容。**

`revert_one` 原来的顺序是「干净备份 → 保险库 → 按标记裁剪」。对**纯插入**型注入
（`cblock` 注释块、`jslit` 的注释块分支）这套顺序是错的：快照会把拍快照那一刻的
整份文件搬回来，于是快照之后第三方写进去的东西一起没。

实际会撞上的场景：`~/.dsh/profiles/desktop/cordis.patch.yml` 是一层公开的 patch
层，用户自己、别的 preset 安装器都往里写。这台机器上就躺着一段用户自己的 preset
声明，保险库里对应的是 11-08 的 827 字节空壳 —— 一次 `--revert` 会把它整个覆盖。

现在的判据：

| 形态 | 撤回方式 |
|---|---|
| `cblock` 注释块 / `jslit` 的注释块分支 | 块在就按标记裁剪，只删我们那几行；块不在就是没残留，直接返回 |
| 整文件 / 字段注入 / JS 字面量替换 | 重建不出原样，照旧走干净备份 → 保险库 |

为什么块标记优先：它是自描述的，剪掉它正好等价于撤销我们那次插入；快照不是，
它只知道「那天的文件长什么样」，不知道这中间谁又写过。

实测（用真实 profile 的副本，配一份 827 字节的旧快照）：

```
revert_one -> True
POJIA 块还在: False       ← 该撤的撤了
麦麦块还在: True          ← 别人的写入保住了
会话守卫块还在: True
用户自己的 ui-chat 行还在: True
约 31 KB -> 约 11 KB，YAML 解析通过
```

旧代码在同样输入下会把文件覆盖成 827 字节。

另一个细节：`cblock_put` 在正文和块之间会加一个空行做分隔，剪块时得把这一行也认
回来，否则撤回后文件会多一个空行。原始文件到底有没有以换行结尾，文件本身说不清，
所以只有「正文一致、仅差行尾空白」时才用备份的形状，正文对不上就保留剪出来的结果
——宁可多一个空行，也不抹掉别人的内容。

## 其他变更

- 新增 8 条契约用例（`tests/contract/test_revert_scope.py`）：有干净备份也不许覆盖
  别人的块、块不在时不许搬快照、自建文件剪空即删、JS 字面量替换仍走备份还原、
  三种行尾形状（带换行 / 不带换行 / 空文件）字节级还原。
- `docs/spec/40-targets.md` 的 7.2 撤回规则按上面重写，写明为什么不是「一律先看备份」。
- pytest 121 passed，selftest 20/20。
