# 破甲修改器 v1.01.9-beta

测试版。这一版修的是「下载完了、程序也关了，然后卡在 find 上不动」。

## 现场

```
[失败] 落盘失败 ...   ← 1.01.8 修掉的那个
```

补上 `state/` 之后，下载通了，窗口也自己关了，接着就是一个黑窗口停在
`find` 那一行，一直不动。等多久都不动 —— 它在**扫盘**。

## 为什么

换装批处理里判断「主程序还在不在」是这么写的：

```bat
tasklist /fi "imagename eq pojia-modifier.exe" 2>nul | find /i "pojia-modifier.exe" >nul
```

`find` 没写全路径。机器上装了 Git for Windows、而程序又是从 Git Bash 那类
环境里拉起来的，PATH 里排在 `System32` 前面的是 `usr\bin\find.exe` ——
**GNU 的 find**。

在 GNU find 眼里，`find /i "pojia-modifier.exe"` 是「从路径 `/i` 开始遍历，
顺便看看 `pojia-modifier.exe`」；MSYS 再把 `/i` 翻译成 `I:\`。于是它开始
递归整个 I: 盘，输出丢进 `>nul`，屏幕上一个字都没有，看上去就是死在那儿。

装完之后那条 `start "" 主程序` 也因此永远轮不到，程序不会重开。

## 现在

- 批处理里所有系统工具都写全路径（`%SystemRoot%\System32\tasklist.exe` 之类），
  开头再把 `PATH` 钉回 System32 —— 两道保险，不靠运气的那个 PATH；
- 判断改用 `findstr /i /c:"..."`：`/c:` 是字面匹配，`pojia-modifier.exe` 里那个
  点不再被当通配符（`find` 的 `"x"` 是正则，碰上 `_update_..._setup.exe` 会误判）；
- 安装程序里同一处检查也换了写法：不再 `cmd /c ... | find`，直接调 `tasklist`
  取输出、用 `StrStr` 找进程名 —— 没有管道，也就没有 `cmd /c` 那套引号麻烦。
  这样从终端里手动跑 setup 也不会卡在开装之前。

## 现在卡住了怎么办

那个黑窗口里跑的是 GNU find，杀掉它就等于给循环一个「进程不在了」的答案，
批处理会自己往下走：

```powershell
Stop-Process -Name find -Force -ErrorAction SilentlyContinue
```

不想等它自己走，也可以直接双击那个已经下好的安装包：

```
%LOCALAPPDATA%\Programs\pojia-modifier\state\_update_pojia-modifier-windows-x64-setup.exe
```

从资源管理器双击是干净的 PATH；命令行里跑的话加 `/S /POJIA_SELFDEL`，
静默模式会跳过「正在运行」这段检查，装完顺手把安装包删掉。
