# 破甲修改器 v1.01.6-beta

测试版。这一版修的是「点了升级，然后就没反应了」。

## 那次其实换成功了

1.01.3 里点「安装新版」会下那个 12 MB 的便携 exe，写一段批处理丢到后台，然后打印：

> 已安排替换，本进程退出后自动换装并重启

问题就在这句话：**「本进程退出」得你自己关窗口**。批处理是 `move` 老 exe、`move` 新
exe、再 `start` 起来的死循环，只要窗口还开着，它就一圈一圈重试，屏幕上什么都不会动。
而且它没有上限 —— 你不关，它就一直等。

真到你把窗口关掉，替换其实是成功的（程序确实起来了，版本也确实变了），但旧标签页
黑在那里、新窗口没人提示 —— 看起来还是「没反应」。

## 现在这条路上没有「你自己关」这一步

- 界面在打印「已安排升级 / 已安排替换」之后 **1.5 秒自己退出**，页面盖一层
  「正在升级…这个页面可以关掉了」；
- 批处理最多等 15 秒，等不到就 `taskkill /f`，不再无限循环；
- 换完把 `pojia-modifier.exe.old` 删掉，不留一个没人用的同名文件。

绿色版（便携）和装过的版本走两条不同的换装路，但这一步是同一个：进程先退场，
文件才换得动。

## 顺带：用 setup 装的程序，现在认得出自己是装过的

判定「我是不是装出来的」原来只读程序目录里的 `install.json` —— 那是 Linux/macOS
安装器的账本，Windows 的 setup 根本不写它，只登记注册表里的 `InstallDir`。

结果是用 setup 装出来的人，升级时被当成绿色版：

- 下的是 12 MB 的便携 exe，不是 9 MB 的安装包；
- 那个便携 exe 被塞进 onedir 目录、顶掉原来的 exe，旁边的 `_internal/` 一整套
  就此成了没人再用的死文件（还能跑，因为是单文件版自己解包，但白占一百多兆）；
- PATH、开始菜单、卸载项都不会跟着更新。

现在两处都认注册表：装过就下安装包，`_internal` 跟着一起换，卸载项和 PATH 也由
安装程序重新登记。

## 已经卡在旧版本上的人

1.01.3 那份自己是修不好的（毛病就在它身上）。关掉窗口，批处理会把新版换上去并
重新打开；实在不动就手动跑一遍新下载的 setup。
