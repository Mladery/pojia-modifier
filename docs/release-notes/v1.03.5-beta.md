# v1.03.5-beta

测试版。恢复上一代有、这一代丢掉的那一层：**DSH 会话守卫**。人格文本只在会话
开头读一次，模型中途拒答它帮不上；这一版把运行时那层补回来。

## 新增能力

### DSH 会话守卫（`--session-guard`）

一个 Cordis 插件，挂在会话上，只做一件事：一轮结束后看一眼怎么收的，该续就替
用户补一句话。

| 收尾形态 | 动作 |
|---|---|
| 命中拒答句式（"我不能协助""出于安全考虑"…） | 补一句"继续把上一件事做完……" |
| 报错，且错误码不在致命名单 | 补一句"继续" |
| 一个字都没吐出来 | 补一句"继续" |
| 正常交付 / 用户按了停止 / 用户刚发过话 / 收件箱还有活 | 不动 |

落点和 Git Bash 接管同构：`<profile>/node_modules/pojia-session-guard/` 两个文件 +
`cordis.patch.yml` 里一段带标记的 `- insert:`。幂等、可撤回，删掉标记段即卸载。

**不跟用户抢方向盘**，四条边界都写在插件里：

- 用户自己按停止 —— `agent/turn-stopping` 的 `signal.aborted` 是唯一可信信号；
- 用户刚发过话 —— `source.kind === "user"` 的入库才算数，自己补的那句不算；
- 自证口令回执、完整性告警绝不当拒答去补；
- 续跑每轮最多一次、每会话有上限；拒答每轮 2 次、整会话 6 次熔断。

补进去的消息自报家门（`source.kind = "pojia-session-guard"`、`form: notice`），
所以它不会被自己的判据当成"用户刚说过话"，对话记录里也看得出这句是谁补的。

### 与破甲模式的关系

`--dsh-mode preset` 是静态预设：用户在模式下拉里手动选中，会话开头读一次。
守卫是运行时的，两种模式都装 —— 预设模式不改任何官方文件，正需要这一层兜底。

## 实现说明

- 只用公开钩子：`agent/status`、`agent/turn-stopping`、`agent/error`、
  `agent/inbox/inserted`。会话日志的同步读接口（`session.snapshotEvents`）已标
  废弃、禁止新调用，插件一次都不碰，改从 `session.deriveMessages()` 取最后一条
  消息。
- 状态翻到 `idle` 后延迟 600 ms 再判：让这一轮彻底落定，也让用户那句"等等"
  来得及进收件箱。
- 新增契约测试 11 条，其中一条把插件真跑一遍（假 ctx / 假 agent，喂六种收尾），
  一条用 `node --check` 验语法。

## 其他变更

- 落盘前先过 `yaml_ok`：破甲模式、Git Bash 接管、会话守卫三段写同一个
  `cordis.patch.yml`，任何一段把文件写坏都会让 DSH 起不来。新增用例覆盖三者共存。
- `--session-guard` 不带 `--apply` 时是独立入口，只装卸插件、不碰人格文件。
- 文档同步：`30-inject.md` 补 2.8 节（四个事件、判据表、上限、来源标记），
  `50-cli.md` 补参数，`40-targets.md` 补验收要点。
