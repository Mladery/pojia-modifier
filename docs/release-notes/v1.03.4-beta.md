# v1.03.4-beta

测试版。两件事：定位链补齐上一代有、这一代丢掉的四个来源；codex / claude /
kiro 这几个工具型目标恢复分层特化注入。

## 问题修复

- **进程反推不再只靠命令行。** 原来要求命令行里含 `_npx` / `node_modules` /
  `program files` 三者之一 —— 双击启动、或套壳启动器把 exe 名当参数传的机器，
  这一层必然空手。现在先问内核要镜像路径
  （`QueryFullProcessImageNameW` / `/proc/<pid>/exe`），命令行只当兜底。
- **桌面和开始菜单被重定向后找不到快捷方式。** OneDrive 备份、组策略漫游配置、
  各种「桌面搬家」工具都会改 `User Shell Folders`，拼 `%USERPROFILE%\Desktop`
  一律指空。现在逐个问 `SHGetFolderPathW`，取不到再读 HKCU + HKLM 两处注册表；
  公共桌面、公共开始菜单、任务栏固定项也一并收进来了。
- **卸载登记表少读两个字段。** 只读 `InstallLocation` / `DisplayIcon`，而大量
  Electron 应用只写 `UninstallString`。现在四种写法都认，MSI 产品码直接放弃。
- **WorkBuddy 国际版会串到国内版。** 国际版没覆盖 `exe` / `procs`，拿
  `WorkBuddy.exe` 去找，命中的是国内版的根。已按 `WorkBuddyAI.exe` 分开。

## 新增能力

### 切换工具配置反查

`wb-switch` / `cc-switch` 必须记住每个版本的绝对路径，否则切不过去。一台机器
装了国际版 + 国内版、还散在不同盘时，这是唯一能同时找到两个根的来源。只读文本
配置，正则抠盘符路径，不解析格式（这些工具换过好几版配置结构）。实测本机
`H:\Workbuddy` 与 `J:\Workbuddy-GLOBAL\WorkBuddyAI` 都能命中。

### 分层特化注入

特化段从「每个目标一句话」恢复成上一代的分层写法：层文本共享，多个目标叠同一份。

| 目标 | 叠加的层 |
|---|---|
| codex | 执行纪律 |
| claude | 执行纪律 + Claude（要拒绝就指名编号） |
| kiro | 执行纪律 + Claude + Kiro（Supervised 审批、steering 全量加载、spec 不拖延） |
| zcode | 执行纪律 + GLM（认身份 + 判定样板） |
| antigravity | 执行纪律 + Gemini（规则从哪来、思考通道、三条化解捷径、三处机制坑） |
| reasonix / traecn / qodercn | 执行纪律 + 各自的加载层与审批语义 |

改一处，所有引用它的目标同时生效。

### Antigravity 拆双文件

单文件 24,000 字节封顶、超出**从尾部截断**，而自证段恰好在最后 —— 超一点就等于
没注入。正文拆成 `GEMINI.md`（政策本体）与 `config/rules/pojia.md`（执行纪律 +
Gemini 专用段，带 `trigger: always_on` 前置头），实测 19,320 + 5,643 字节，
两边都不接近上限。

## 其他变更

- 往上找安装根时，`bin` / `resources` / `Program Files` 这类通用目录名永不判成
  安装根；盘符根收手；判据优先用目标自己的标志物，不再拿「任何目录都算」的宽松
  判据往上层翻。
- `tools/selftest.py` 的 wb / wbintl 假安装补上带 `<content_policy>` 的模板与
  `cli/product.json`。替换式注入只改原生政策段，旧假安装里没有那一段，apply 只
  回一句「已是最新」，这两个目标的往返自检之前等于没验。
- 文档同步：`docs/spec/20-locate.md` 兜底链从 7 条扩到 11 条，
  `30-inject.md` 补分层规则，`40-targets.md` 更新 Antigravity 落点。
