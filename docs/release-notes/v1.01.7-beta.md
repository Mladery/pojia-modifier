# 破甲修改器 v1.01.7-beta

测试版。这一版把「更新」从一条横幅变成一张卡片：在设置页点一下就查，查到了就地装，
下载到哪儿了当场看得见。

## 以前只有顶上那条提示

有没有新版，全靠启动时顶上飘出来的横幅。它只在**启动那一刻**查一次，错过了就得重开。
点「安装新版」之后人还会被拽到「运行记录」页 —— 那页是给跑动作看的，升级的十几行
输出混在里面，跟 `[ok]` `[fail]` 挤在一块，反而看不出进行到哪一步了。

## 设置页现在有「检查更新」

就在通道选择下面，一个按钮一个结果：

```
[检查更新]   已是最新（v1.01.7-beta）
[检查更新]   有新版本 v1.01.8-beta（当前 v1.01.7-beta）   [安装 v1.01.8-beta]
```

查到新版右边才长出「安装」按钮 —— 没有新版就不给一个点了会报错的按钮。
点「安装」之后**人留在这一页**：通道、检查按钮、升级日志在同一个屏幕上，
不用来回切页面对时间线。

## 下载进度是真的在读字节

`http_get` 改成 64 KB 一块地读，每块回报一次 `(已读, 总长)`。界面在跑的时候才吐：

```
#progress 100 5.0 5.0
```

`#progress <百分比> <已下 MB> <总 MB>` —— 界面按空格切成三段，进度条和下面的
`46% · 4.6/10.1 MB` 就是这几行喂出来的。

CLI 那边不吐这行：`pojia --check-update` 是给人读的，冒一串机器格式没意义。
分流的开关是环境变量 `POJIA_GUI=1`，由界面进程往下传，核心代码自己不猜。

CDN 有时不给 `Content-Length`，那 `总长` 就是 0，进度条按 0% 显示、只报已下载的量，
不会卡在一个永远到不了的 99%。

## 装没装成，这一页也说得清

- 成功：照 1.01.6 的老路，1.5 秒后盖一层「正在升级…这个页面可以关掉了」，进程自己退场；
- 失败：红字写「升级没有完成，看上面的输出」，**并且把「安装」按钮放回来** ——
  刚才藏起来是为了防重复点，现在没装成，得能直接再来一次，不用先重查一遍；
- 没查到可装的：写「没有可装的更新」，不留一个悬着的按钮。
