# v1.03.8-beta

测试版。自更新卡死的**真根因**修复。1.03.7 修的是卡死尾巴上的黑窗，这次修的是
卡死本身。

## 现象

从 1.03.5 起，每次用界面升级都在同一步停下：下载、校验都正常，然后出现一个
命令行长窗口，停在那儿不动；手动结束它，后台安装程序才开始跑。

## 现场

实机抓到的进程快照：

| 进程 | 状态 |
|---|---|
| `cmd.exe`（换装批处理） | 活着，停在 `:wait` |
| `tasklist.exe` | 早已退出 |
| `findstr.exe` | **活着两分钟**，等 stdin |
| `conhost.exe` | **父进程是 findstr** |

## 根因

换装批处理由 `DETACHED_PROCESS` 拉起 —— 它**没有 console**。批处理里的
`tasklist | findstr` 是这条链上唯一的管道，而 tasklist 是 console 程序：

1. 无 console 的进程拉起 console 程序时，系统给它临时配一个 conhost；
2. **conhost 会把父进程的句柄表继承下来**，其中包括管道的写端；
3. tasklist 干完活退出，写端本该关闭 —— 但 conhost 还按着一份；
4. findstr 读不到 EOF，永远等下去。

整条换装链就停在这里。手杀那个窗口等于杀掉 findstr 和 conhost —— 句柄一松，
`if errorlevel 1 goto swap` 的下一轮立刻放行，安装程序才开跑。这也解释了为什么
「结束命令行之后安装才开始」。

为什么不是每次必现：DETACHED 下 console 的分配与 conhost 的继承时机跟系统负载
有关，所以表现是「总有点问题」而不是「每次都卡」。

## 修复

**换装批处理：整条链不再有管道。**

原来：

```bat
:wait
"%SystemRoot%\System32\tasklist.exe" /nh /fi "imagename eq pojia-modifier.exe" | "%SystemRoot%\System32\findstr.exe" /i /c:"pojia-modifier.exe" >nul
if errorlevel 1 goto swap
```

现在：

```bat
rem 页面 1.5 秒自己退出，这里等 7 秒足够
"%SystemRoot%\System32\ping.exe" -n 8 127.0.0.1 >nul
"%SystemRoot%\System32\taskkill.exe" /f /im "pojia-modifier.exe" >nul 2>&1
"%SystemRoot%\System32\ping.exe" -n 2 127.0.0.1 >nul
:swap
```

行为变化：从「轮询检测进程，15 秒后强杀」变成「固定等 7 秒，然后无条件强杀」。
taskkill 对已经不存在的进程报个 128 就完了，不用看任何输出。绿色版分支同理，
`move` 重试从「每轮查一次进程」改成 `for /l` 循环试 10 次，循环里只有 move 和
ping，也没有管道。

**进程拉起方式：`DETACHED_PROCESS` → `CREATE_NO_WINDOW`。**

`CREATE_NO_WINDOW` 给整个进程树一个**隐藏** console：窗口照样看不见，但 console
语义是正常的 —— 子进程共享同一个 conhost，管道 EOF 能送达。双保险：即使将来有人
往批处理里加了管道，也不会再走到这条死锁上。

**测试加锁。**

- `test_swap_batch_calls_system_tools_by_full_path` 改成反断言：批处理里**不许**
  出现 `tasklist`、`findstr`、任何 `|`。谁想加回去，先过这条。
- 新增绿色版分支覆盖（`test_green_batch_has_no_pipe_either`）。
- 批处理实跑测试会把 `taskkill` 行替换成 `rem` 再跑：这段代码是在用户机器上跑的，
  照原样执行会杀掉正在开着的界面。

## 校验

- pytest：122 passed（更新链 21 例，含新增的绿色版分支覆盖）
- 新批处理全文核对：零管道、ping/taskkill 全路径、`:swap` 标签保留
- 现场已解卡：卡死的 findstr / cmd / conhost 已清理，TEMP 残留批处理已删

## 注意

这一版要用 **v1.03.8 的包**升级才会走新批处理。从 1.03.7 及以前升级到 1.03.8 时，
用的还是旧批处理（旧代码已经刷进旧版 exe 里了）——**那一次可能仍会卡**，卡了就
结束那个命令行窗口，安装会继续。从 1.03.8 往后不会再出现。
