# v1.03.9-beta

测试版。修的是 **macOS 上「除了 zcode 和 codex，其余全是未安装」**（issue #2）。

## 现象

mac 用户报：装机后 `--status` 里只有 `zcode`、`codex` 两行有状态，claude、
antigravity、cursor、windsurf 等等一长串全是「未安装」。同一台机器换旧版
pojia-ce 就正常。

## 根因一：默认位置套了强判据

默认位置（`~/.claude`、`~/.gemini` 这种产品专属目录）原来也要过 `is_valid`：
**必须命中 markers 里的某个文件**才算装了。

问题是这些目录里常年没有 marker：

| 目录 | 实际内容 | 标志物（旧判据） |
|---|---|---|
| `~/.claude` | `projects/`、`settings.json`、`todos/` | `CLAUDE.md`、`skills/` ← 都没有 |
| `~/.gemini` | `settings.json`、`tmp/` | `GEMINI.md`、`antigravity/` ← 都没有 |
| `~/.cursor` | `projects/`、`chats/` | `.cursorrules`、`rules/` ← 都没有 |

于是全判成未安装。而 `zcode` 的 markers 是**空**（目录在就算）、`codex` 恰好有
`config.toml` —— 这两个成了唯二能认出来的，跟 issue 描述一字不差。旧版判据是
`isdir(home)`，所以旧版没这个问题。

判据现在分两种用法：

| 场景 | 判据 |
|---|---|
| 默认位置 | 目录存在 **且里面非空** |
| 兜底候选（深搜 / 进程反推 / 注册表 / 快捷方式） | 目录存在 **且含标志物** |

空目录仍然不认 —— 那是 `mkdir` 出来的空壳，不是客户端。

## 根因二：三条路径是 Windows 形态

| 目标 | 问题 |
|---|---|
| `reasonix` | 默认根拼成 `<home>/AppData/Roaming/reasonix`，非 Windows 上永远不存在。旧版有平台分支（`~/.reasonix`），搬家时丢了 |
| `dsh` | 只认 `resources/app.asar`、只扫盘符，都是 Windows 形态；`.app` 包内资源在 `Contents/Resources/` 下，多一层 |
| `wb` / `wbintl` | 安装根只找 `%LOCALAPPDATA%\Programs\*`，macOS 上桌面端就是 `/Applications/*.app` |

逐一补齐：

- **Reasonix**：`default_root()` 按平台分支，Windows `%APPDATA%\reasonix`、
  其余 `~/.reasonix`。
- **DSH**：`is_install` 认 `Contents/Resources/app.asar`；新增 `resource_base()`
  统一取资源目录（两套路径写两遍迟早对不上）；盘符全扫加 `IS_WIN` 前提。
- **DSH 兜底**：安装根找不到、但 `~/.dsh/profiles/*/cordis.patch.yml` 在时，
  直接把配置根当 root（来源记「配置目录（无安装根）」）。preset 模式、会话守卫、
  profile 注入全在配置根，一个字节都不需要安装目录 —— 这条是 mac 上跑通的唯一路。
- **WorkBuddy**：`install_candidates()` 加 `/Applications/WorkBuddy(app|AI).app`
  与 `~/Applications/...`；新增 `resource_root()` 取 `Contents/Resources`；
  `templates()` / `product_json()` 跟着走；`is_intl()` 在 mac 上按包名判。

## 校验

- pytest：141 passed（新增 `tests/contract/test_locate_mac.py` 19 例）
- selftest：20/20
- 新增用例钉住的线：
  - `~/.claude` 只有一个 `projects/` → 识别为默认位置（issue 的正例）
  - 空目录 → 仍然是未安装（放宽不等于全放）
  - `~/.gemini` 只有 `settings.json` → 识别
  - Reasonix 非 Windows 默认根 = `~/.reasonix`
  - DSH 认 `Contents/Resources/app.asar`；`resource_base` 取到 `Contents/Resources/app`
  - DSH 安装根缺失、profiles 存在 → 回配置根；只有空 `~/.dsh` 时不许当配置根
  - WorkBuddy 候选含 `/Applications/*.app`；`resource_root` 取 `Contents/Resources`；
    包名判国际版

## 注意

macOS 上的 `.app` 改动是**只读识别 + 路径拼接**，没有真机验证过 —— 手上只有
Windows。识别层有测试兜住；如果 mac 上仍有目标认不出，把 `--status` 的输出发到
issue #2，按实际目录名补候选。
