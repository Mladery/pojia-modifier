# v1.03.7-beta

测试版。两块修复：Trae CN 适配新版布局，自更新的尾巴不再弹黑窗。

## Trae CN：全局规则落点搬迁（1.107.0 起）

Trae CN 升到 1.107.0 之后，全局规则不再读 `~/.trae-cn/rules/project_rules.md`。
全局层只认两处：

| 位置 | 说明 |
|---|---|
| `~/.trae-cn/user_rules.md` | legacy 单文件，存在才读 |
| `~/.trae-cn/user_rules/**.md` | 目录递归，最多 3 层 |

旧落点写进去就是死文件；而全新安装的 `~/.trae-cn` 连 `rules/` 目录都没有，
定位标记三个全落空，`--status` 一直显示「未安装」，`--apply` 根本写不进去。

本版的适配：

- 落点改成 `~/.trae-cn/user_rules/pojia.md`（目录式，官方形态）
- 定位标记加 `argv.json`：它在 `~/.trae-cn` 常驻，全新安装、一份规则没写过
  也在，默认位置这源不再空手
- 进程反推重写。安装根（`AppData\Local\Programs\Trae CN`）与配置根
  （`~/.trae-cn`）不在一条祖先链上，原来的「沿目录往上找合法根」对它永远
  空手；现在只借运行中的进程确认 CN 版在跑，落点直接回默认配置根
- 体检清单里把自己那份从「同时在生效」的计数里排除；旧落点如果还躺在盘上
  （老版 CN 写过再升级的场景），给一行提示，`--revert` 按护照照常能清

国际版 Trae（1.100.3）还是旧逻辑，`trae` 目标不受影响。

## 自更新：卡住的命令行窗口

用户实测 1.03.5 → 1.03.6：升级本体走通了（文件装上、GUI 重开），但最后弹出
一个卡住的命令行窗口，看着像 find 卡死，手杀之后盘上还留着
`pojia-del-setup.cmd` 和 setup.exe。

根因是安装器的 `ExecShell` 四参语法用错了位：

```nsi
ExecShell "" "$0" SW_HIDE      ; SW_HIDE 落进了「参数」位
ExecShell "" "$0" "" SW_HIDE   ; 参数占一个空串，SW_HIDE 归到显示方式
```

本该隐藏的删除批处理弹成一个可见黑窗：循环删 setup.exe（每次 ping 一秒），
杀毒扫描锁着文件期间删不掉，窗口里没有任何输出——看着就是命令行卡死。窗口
被手杀后批处理到不了自删那行，残留就永远留在盘上。

配套修了两处：

- 删除批处理的 `ping` 带全路径（`$SYSDIR`），不吃继承来的 PATH；循环 30 次
  加到 60
- GUI 的退场判定原来在最后 20 行输出里找「已安排」；下载进度行一多就可能把
  关键行挤出窗口，GUI 不退场，批处理只能干等 15 秒 taskkill 兜底。现在读流
  时单独累积一个布尔，与滑窗解耦
